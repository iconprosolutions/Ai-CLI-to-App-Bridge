# How AI CLI Bridge Works

> Architecture explainer for the v2 consolidated bridge. Companion docs:
> `RUNBOOK.md` (operations), `STATE.md` (project status),
> `superpowers/specs/2026-07-02-bridge-v2-design.md` (the design decisions).

## What this is

You pay flat-rate subscriptions for two AI CLIs — Claude Code (`claude`) and
Google Antigravity (`agy`). This app wraps both behind one **OpenAI-compatible
HTTP server** on port 9011, so any tool that speaks the OpenAI API (Hermes,
OpenAI SDKs, curl) can use your subscriptions as if they were API models —
with streaming, tool calls, JSON mode, per-app usage accounting, and a web
control center.

## The 30-second mental model

```
                        ┌──────────────────────────────────────────────┐
  Hermes / SDK / curl   │        provider process  (:9011)             │
  ───────────────────►  │                                              │
  POST /v1/chat/…       │  auth → validate → route → breaker → queue   │
                        │            │                                 │
  Browser               │            ▼                                 │
  ───────────────────►  │   ┌─ claude adapter ──► spawn `claude -p     │
  /dashboard/…          │   │      (stream-json)    --output-format    │
                        │   │                       stream-json` ◄─────┼── stdin: prompt
                        │   └─ agy adapter ─────► spawn `agy --print…` │
                        │                                              │
                        │  telemetry · usage ledger · capture · events │
                        └──────────────────────────────────────────────┘
```

**One process owns everything.** There is no HTTP hop between the API surface
and the engines — the "adapters" are in-process modules that spawn the CLI
binaries directly. That's why every dashboard button works: the process that
renders the kill button is the same process holding the CLI child to kill.

## Life of a request

What happens when Hermes sends
`POST /v1/chat/completions {"model":"bridge-claude-sonnet-4.6-northstar", "stream":true, ...}`:

1. **Auth** — bearer token compared timing-safely against the key in
   `.bridge-runtime/credentials.json` (auto-generated by the launcher, 0600).
2. **Validation** — messages shape, roles, no images (400 — honestly
   unsupported, not silently degraded), `n=1` only, `logprobs` rejected.
   Ignored sampling params (`temperature` etc.) are noted and echoed back in
   `bridge_ignored_params`.
3. **Routing** — `"bridge-claude-sonnet-4.6-northstar"` (or an alias like
   `bridge-smart`) is looked up in `packages/provider/routes.json`, which maps
   route id → engine (`claude`) + upstream model (`claude-sonnet-4-6`). This
   file hot-reloads; the dashboard's Routes tab edits it through `/admin`.
4. **Circuit breaker** — if this engine recently exhausted its quota (2
   consecutive quota failures), the circuit is *open*: the request fails
   immediately with `429 + Retry-After` and **no CLI is spawned**. After a
   15-minute cool-down one trial request is let through (half-open); success
   closes the circuit.
5. **Concurrency gate** — one CLI run per engine at a time (subscription-
   friendly). A short FIFO queue (depth 4, 30 s) absorbs bursts; beyond that,
   `429 engine_busy`.
6. **Prompt flattening** — the OpenAI `messages` array becomes one text
   prompt with `[SYSTEM]/[USER]/[ASSISTANT]` blocks. If `tools` were sent, a
   system block teaches the model to answer with a ```json tool_calls block.
   If `response_format` was sent, a system block demands JSON.
7. **CLI invocation** — the engine adapter spawns the binary via the shared
   runner (`packages/core/cli-runner.js`):
   - prompt is written to **stdin** (argv would break past ~1 MB and leak the
     prompt to `ps`),
   - output is decoded with StringDecoder (multibyte chars can't split),
   - a byte cap, wall-clock timeout, and AbortSignal all lead to
     SIGTERM → 2 s → SIGKILL,
   - every live child sits in a registry so process shutdown reaps them all.

   **Claude** runs `claude -p --output-format stream-json
   --include-partial-messages --verbose --model <m>`. That emits NDJSON
   events: the adapter forwards `text_delta` events as live streaming deltas
   (skipping thinking/signature deltas) and reads the final `result` line for
   the authoritative text, stop reason, and **real token usage** (input +
   cache buckets + output).

   **Gemini/agy** runs `agy --print <prompt> --model <m>`. Text-only: deltas
   pass through a streaming ANSI stripper (escape codes split across chunks
   are carried, spinner `\r` frames collapsed). No token counts, so usage is
   estimated (~4 chars/token) and labeled `estimated`.
8. **Streaming back** — the provider writes SSE chunks in OpenAI's
   `chat.completion.chunk` format. A *pacer* splits chunky CLI flushes into
   word-sized deltas every 10 ms (bounded: never adds more than ~2 s total,
   stops instantly on abort, honors socket backpressure). Heartbeat comments
   (`: ping`) every 15 s keep idle streams alive while a CLI thinks.
9. **Tool calls** — if the request had `tools` and the reply is a
   ```json tool_calls block, streaming *held back* the content (up to 2 KB)
   so raw JSON never renders in the client; the provider emits proper indexed
   `tool_calls` deltas with `finish_reason: "tool_calls"` instead. Replies
   that merely *mention* tool_calls are left alone when no tools were sent.
10. **JSON enforcement** — for `response_format`, the reply is run through
    `extractJson` (fences/preamble tolerated) and, for `json_schema`, a
    dependency-free schema validator. On failure the provider makes **one**
    corrective retry ("your reply wasn't valid because …, reply with only
    corrected JSON"), then gives up with 502.
11. **Recording** — every request lands in three places:
    - **telemetry** (in-memory, last 200): powers the Overview tab,
    - **usage ledger** (`.bridge-runtime/usage/YYYY-MM.jsonl`, durable,
      bodies never written): powers the Usage tab,
    - **capture** (only when toggled on): full prompt/output + stage timings
      in a memory-only ring buffer of 50, for the Requests tab.
    An SSE event (`request.start`/`request.end`) pushes each change to any
    open dashboard.
12. **Failure mapping** — every error is a typed `BridgeError` whose `kind`
    maps to HTTP exactly once (`packages/core/errors.js`):

    | kind | comes from | HTTP |
    |---|---|---|
    | `quota` | "usage limit reached" / "exhausted your capacity" | 429 + Retry-After, `rate_limit_error` |
    | `timeout` | CLI exceeded its 5-min budget | 504 |
    | `model_not_found` | CLI rejects the model | 400 `invalid_model` |
    | `invalid_request` | e.g. prompt too big for agy's argv | 400 |
    | `spawn_failed` / `bad_output` | binary missing / garbage output | 502 |
    | `aborted` | client hung up or admin killed it | 499 (telemetry only; never counts against engine health) |

    Quota and timeout failures also feed the circuit breaker.

## The packages

```
packages/
  core/        @bridge/core — shared, dependency-free
    cli-runner.js     THE way to run a CLI (stdin, caps, kills, registry,
                      installGracefulShutdown)
    errors.js         BridgeError taxonomy + httpFor() mapping
    ansi.js           stripAnsi, streaming stripper, CR collapse
    json-extract.js   fence/preamble-tolerant JSON extraction
    json-schema.js    minimal validator for response_format json_schema
    pacer.js          smooth streaming pacer (lossless, bounded, stoppable)
    auth.js           timing-safe bearer middleware
    context-store.js  async file store w/ per-file write locks (legacy /api)
    sessions.js       bounded session registry (legacy /api)
    config.js         env helpers

  adapters/    @bridge/adapters — one file per engine
    claude.js         stream-json invocation, real usage, quota classifier,
                      auto-fallback to text mode on old CLIs
    agy.js            argv guard, ANSI transform, free `agy models` listing

  provider/    @bridge/provider — the server on :9011
    server.js         wiring: auth, /v1, /dashboard/*, /admin, shutdown
    routes.js/.json   route registry: validate, hot-reload, admin mutations
    translate.js      OpenAI messages ⇄ prompt, tool-call parsing
    breaker.js        per-engine circuit breaker
    semaphore.js      slot + bounded FIFO wait queue
    telemetry.js      in-memory window + health history
    usage.js          durable JSONL ledger + pricing rollups
    pricing.json      editable API list prices ($-equivalent column)
    capture.js        opt-in ring buffer of full exchanges
    events.js         SSE event bus (/dashboard/events)
    admin.js          key-gated control endpoints
    dashboard/        index.html + styles.css + app.js (no build step)
```

## The dashboard

Static files served at `/dashboard/`; all data comes from four endpoints:

| Tab | Reads | Acts via |
|---|---|---|
| Overview | `/dashboard/status`, `/dashboard/usage?range=today`, SSE | `/admin/breakers/:e/reset`, `/admin/requests/:id/kill`, `/admin/engines/:e/*` |
| Routes | `status.routes` | `POST/PUT/DELETE /admin/routes`, `/admin/engines/:e/probe` |
| Usage | `/dashboard/usage?range=` | — |
| Tester | `status.routes` | `POST /v1/chat/completions` (SSE or blocking) |
| Requests | `GET /admin/capture(/:id)` | `POST /admin/capture {enabled}` |
| Connect | `status.connection` | stores the API key in localStorage |

Live updates: `EventSource('/dashboard/events')` triggers a throttled status
refresh on every request/breaker/health/capture event; if SSE drops, the page
falls back to 10 s polling. The header verdicts (READY/BUSY/BLOCKED/DOWN/OFF)
are derived from breaker state + health + inflight + disabled flags.

Everything under `/admin` requires the bearer key even when `/v1` runs open;
`/dashboard/status|usage|events` are unauthenticated but the server binds to
127.0.0.1 by default, so only your machine can reach them.

## What's legacy (still in-tree, not used by default)

`claude-bridge/`, `gemini-bridge/`, `provider-bridge/` are the v1
three-process stack. They still work (tests keep them green) and are used by
`docker-compose.yml` and any old `/api/chat`-`/api/process`-`/api/contexts`
consumers. The launcher starts them only by explicit name
(`node scripts/bridge.js up claude`). The consolidated provider replaced the
v1 `provider-bridge` for all `/v1` traffic.

## How it's tested without burning quota

`tests/fixtures/fake-cli.js` is a scriptable stand-in for both CLIs: it can
emit claude's stream-json framing (with fixed token counts), agy-style ANSI
output, split multibyte characters across writes, flood, hang, or die with a
quota message — and it logs its argv so tests can assert exactly how the CLI
was invoked (or prove it *wasn't* spawned, e.g. when the breaker is open).
Five suites, ~330 assertions: `npm test`.
