Sign in to claude.ai as the account you're adding before clicking the link. Or paste a claude setup-token below instead.

Where the credential comes from

claude — on any machine with the Claude CLI, run claude setup-token signed in as the account you're adding; approve in the browser and paste the printed sk-ant-oat… token here (valid ~1 year).

gemini — on a machine with a browser, run agy under a scratch HOME (export HOME=/tmp/agy-x && agy), sign in, quit, then paste the contents of /tmp/agy-x/.gemini/antigravity-cli/antigravity-oauth-token here.

The account joins rotation immediately — hit Probe on its card to confirm.

Accounts come from .bridge-runtime/accounts.json (hot-reloaded, validated). With no file, each engine runs one implicit default account whose spawns use the ambient environment. Enable/disable here is runtime-only — edit the file to persist. Each account gets its own circuit breaker and CLI lane, so multiple accounts run in parallel; a quota/auth failure on an un-pinned account fails the request over to the next healthy one exactly once. Unpinned traffic round-robins across accounts; pin a key to an account in the Connect tab to dedicate capacity.

How SaaS mode works

      

        1 · Create a user here and tell them their password (they can change it).

        2 · They sign in at this same URL and see only their own profile.

        3 · They mint one API key per app — named username.app, inheriting the default limits you set.

        4 · Over a limit → their key gets 429 + Retry-After; everyone else is unaffected.

        5 · Usage tab "By user" shows who used what; this table shows today/month per user.
