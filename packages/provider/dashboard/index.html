Accounts

per-engine credential pool · rotation · one-shot failover · needs-login
Accounts come from .bridge-runtime/accounts.json (hot-reloaded, validated). With no file, each engine runs one implicit default account whose spawns use the ambient environment. Enable/disable here is runtime-only — edit the file to persist. Each account gets its own circuit breaker and CLI lane, so multiple accounts run in parallel; a quota/auth failure on an un-pinned account fails the request over to the next healthy one exactly once.
