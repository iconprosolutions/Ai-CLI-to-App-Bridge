01 · The pitch

What this is

One process wraps your two flat-rate CLI subscriptions — claude (Claude Code) and agy (Google Antigravity) — behind a single OpenAI-compatible endpoint at http://127.0.0.1:9011/v1. Any tool that speaks the OpenAI API (Hermes, the OpenAI SDKs, curl) can now call those subscriptions as if they were paid API models — with streaming, tool calls, JSON mode, and per-app usage accounting. A web control center at /dashboard/ lets you watch, test, and steer all of it.

02 · Boot

Start it

  1. From the repo root, bring the consolidated provider up:

    # /Users/waqar/Projects/experiments/ai-cli-bridge
npm run bridge:up

  2. Grab your API key. The launcher prints it on every up and status. It's also stored on disk, mode 0600:

    npm run bridge:status         # prints key + health + pids
# persisted at:
.bridge-runtime/credentials.json

    You never generate this yourself — the launcher auto-creates it on first boot.

  3. Open the control center:

    open http://127.0.0.1:9011/dashboard/

Other lifecycle commands: bridge:down, bridge:restart, bridge:probe (routes + live engine status, quota-free), bridge:logs (add --follow).

03 · Do this first

First-run checklist

⚠ Step 1 is not optional

Open the Connect tab and paste your API key into the key field. It's saved to localStorage, and the Tester plus every admin button read it from there. Skip this and the Tester returns 401 · Missing or invalid Authorization bearer token — that error always means you skipped this step, not that the key is wrong.

  1. Paste the key in Connect. Copy it from bridge:status or credentials.json, drop it into the key field on the Connect tab. Done once, it sticks in the browser.
  2. Fire a test prompt in the Tester. Pick any route, type a one-liner, hit send. A streamed reply confirms auth, routing, and the CLI spawn are all working end-to-end.
  3. Check the Overview verdicts. The header should read READY for at least one engine, with breakers closed and no alert banner. Now you're clear to point apps at it.
04 · Integration

Connect an app

Point any OpenAI-compatible client at the bridge with three things:

Base URL   http://127.0.0.1:9011/v1
API key    # bearer — from .bridge-runtime/credentials.json
Header     X-App-Id: your-app        # enables per-app usage attribution

The X-App-Id header is how the Usage tab splits tokens by app — set a distinct id per consumer.

Hermes

Register a provider named ai-cli-bridge pointing at http://127.0.0.1:9011/v1, and put the key in ~/.hermes/.env as AI_CLI_BRIDGE_API_KEY:

# ~/.hermes/.env
AI_CLI_BRIDGE_API_KEY=<your-key>

# smoke test:
hermes -z "Reply with exactly: ok" --provider ai-cli-bridge \
  -m bridge-agy-gemini-3.5-flash-medium-pulse -t ""

Text and tool-JSON calls work over Hermes; keep tool-heavy agentic loops on a native provider (see the limitations below).

Raw curl

curl http://127.0.0.1:9011/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -H "X-App-Id: scratch" \
  -d '{"model":"bridge-claude-sonnet-4.6-northstar",
       "stream":true,
       "messages":[{"role":"user","content":"Say hi"}]}'

The six routes — and when to pick each

Aliases like bridge-fast / bridge-smart still resolve, but the canonical ids are:

Pulse · default bridge-agy-gemini-3.5-flash-medium-pulse Balanced, fast Gemini. Your everyday default for app calls.
Forge · faster reasoning bridge-agy-gemini-3.5-flash-high-forge Stronger fast reasoning, still Gemini Flash.
Atlas · long context bridge-agy-gemini-3.1-pro-high-atlas Gemini Pro for long context and broad project scans.
Spark · quick Claude bridge-claude-haiku-4.5-spark Claude Haiku — fast, cheap Claude responses.
Northstar · coding / planning bridge-claude-sonnet-4.6-northstar Claude Sonnet — coding, planning, careful reasoning.
Oracle · hard reasoning bridge-claude-opus-4.5-oracle Claude Opus for the hard stuff, when your Claude limits allow.

Rule of thumb: Gemini routes (Pulse/Forge/Atlas) are cheap and fast with estimated token counts; Claude routes (Spark/Northstar/Oracle) give real token usage and better tool/JSON reliability. Long conversations belong on Claude routes — Gemini prompts are capped at 200 KB.

05 · The control center

The dashboard, tab by tab

Overview

Is it safe to fire work right now?

Per-engine cards with breaker state, quota reason, slots/queue depth, and 24 h uptime. The header verdicts summarize everything as READY / BUSY / BLOCKED / DOWN / OFF.

  • Breaker states: closed = healthy, requests flow. open = quota recently exhausted (2 consecutive failures) — requests fail fast with no CLI spawn until the cool-down. half-open = one trial request is allowed through; success closes it again.
  • Alert banner appears whenever a circuit is open, with the retry countdown.
  • Reset breaker clears an open circuit immediately if you don't want to wait out the 15-minute window.
  • Kill-run terminates a stuck in-flight CLI process (SIGTERM → SIGKILL); it's logged as an abort and never counts against engine health.

Routes

Edit the model catalogue

Toggle, add, or delete routes. Edits persist to packages/provider/routes.json and hot-apply with no restart.

  • Probe lists each engine's live catalogue for free — quota-free, no completions run (claude is a static list, gemini asks agy models).

Usage

Durable per-app / per-route / per-day token ledger
  • Claude routes show a REAL badge (token counts come straight from stream-json); Gemini routes show ~EST (estimated at ~4 chars/token).
  • API-equivalent value prices your flat-rate usage at API list prices from the editable packages/provider/pricing.json — it's a "what this would have cost on the metered API" figure, not a real bill. Your subscriptions are flat-rate.

Tester

Fire requests without leaving the browser

SSE or blocking mode, tools JSON, json_object/json_schema modes, side-by-side A/B route compare, and copy-as-cURL. This is where your first smoke test lives — and it needs the key from the Connect tab.

Requests

Opt-in full-exchange capture

The last 50 full exchanges — prompt, output, and per-stage timings.

  • Capture is opt-in: default is metadata-only. Flip it on to record bodies.
  • The buffer is memory-only and cleared on restart or when you toggle it off. Nothing hits disk.

Connect

Where the key lives + copy-paste snippets

Base URL, the key field (stored in localStorage), and ready-made Hermes / curl / JS / Python snippets. This tab is the source of the credential every other admin action uses.

07 · Firefighting

When something breaks

SymptomCause & fix
401 in the Tester
Missing or invalid bearer token		You skipped pasting the key. Go to the Connect tab and paste it into the key field.
429 rate_limit_error
circuit open		That engine's quota is exhausted. Wait for the Retry-After window, or reset the breaker in Overview. Use a different engine's route meanwhile.
429 engine_busyThe per-engine slot (1) plus its queue (depth 4) are full — it's protecting your subscription. Retry after Retry-After.
Engine shows DOWNThe CLI binary isn't on PATH for the launcher. Set CLAUDE_PATH / GEMINI_PATH and npm run bridge:restart.
A reply looks wrongFlip capture ON in Requests, reproduce it, inspect the exact prompt / output / stage timings, then flip capture off (the buffer clears).

Where the logs live

npm run bridge:logs --follow     # tail the provider log
.bridge-runtime/*.log            # provider.log + friends on disk
08 · Mental model

Under the hood in 60 seconds

One process owns everything — there's no HTTP hop between the API surface and the engines. That's why every dashboard button works: the process that renders the Kill button is the same one holding the CLI child to kill.

  client  ─POST /v1/chat/completions─►  provider :9011
                                        │
     ┌──────────────────────────────────┘
     ▼
  auth ─► validate ─► route ─► breaker ─► queue
                                              │
                                              ▼
                                   ┌─ claude adapter ─► spawn `claude -p
                                   │     --output-format stream-json`
                                   └─ agy    adapter ─► spawn `agy --print`
                                              │
  client  ◄────────── SSE chunks ◄────── pacer
